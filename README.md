# Hybrid Hydrocarbons Limited — Project Documentation

This project is a polished corporate landing page for Hybrid Hydrocarbons Limited, built with Next.js, TypeScript, Tailwind CSS, and GSAP animation. The app is designed as a premium single-page experience that helps present the company as a modern energy business bridging traditional operations with sustainable innovation.

## 1. Overview

The website is intentionally structured as a single-page marketing site with distinct sections:

- Navigation and top-of-page branding
- Hero section with cinematic visual treatment
- Company background and impact metrics
- Service overview cards
- Contact section with business details and form
- Footer with legal/branding information

The visual direction uses a high-end corporate aesthetic: clean whitespace, deep neutral backgrounds, red accent highlights, subtle glassmorphism, and layered motion effects.

## 2. Tech stack

This application uses the following critical tools:

- Next.js 14 with App Router
- React and TypeScript
- Tailwind CSS for styling and layout
- GSAP + ScrollTrigger for animation and scroll-linked motion
- lucide-react for vector icons
- shadcn/ui-inspired component primitives for reusable UI pieces

## 4. Configuration files

### package.json

This file defines the project scripts and dependencies.

Scripts:

- `npm run dev` — starts the local development server
- `npm run build` — creates a production build
- `npm run start` — runs the production build locally
- `npm run lint` — checks the codebase for lint issues

Dependencies:

- `next` — core framework
- `react`, `react-dom` — UI library
- `gsap` — animation engine
- `lucide-react` — icons
- `clsx`, `tailwind-merge` — class composition helpers
- `class-variance-authority` — utility for building component variants
- `@radix-ui/react-slot` — used by reusable button primitives

### tsconfig.json

TypeScript configuration for the project. This file enables strict checking and ensures the app supports modern JSX/TS patterns.

### next.config.js

This file is the default Next.js configuration. It allows customization of framework behavior such as image handling, redirects, and optimization settings. In this project, it remains minimal and standard.

### postcss.config.js

This sets up PostCSS, which is required for Tailwind CSS processing.

### tailwind.config.ts

Defines the design system. It extends Tailwind with brand-specific colors, shadows, animations, and font family. Important tokens include:

- `bg` — background colors
- `red` — the primary accent palette
- `ink` — text colors
- `line` — border colors

This configuration also defines custom animations such as float, spin-slow, and accordion transitions.

### next-env.d.ts

This file is generated by Next.js and is required for TypeScript to understand Next.js types.

## 5. App entry and page composition

### app/layout.tsx

This is the root layout for the entire application.

Responsibilities:

- Loads the Inter font using `next/font/google`
- Sets SEO metadata using the `Metadata` object
- Applies the global CSS stylesheet
- Wraps all pages in a consistent HTML shell
- Declares the document language as English

The metadata includes:

- default title and title template
- description focused on the company’s hybrid energy model
- keywords relevant to energy, sustainability, and carbon management
- Open Graph data for social sharing
- Twitter card metadata
- robots rules to allow indexing

The `RootLayout` component renders:

```tsx
<html lang="en" className={`${inter.variable}`}>
  <body className="font-sans bg-bg text-ink antialiased selection:bg-red/30">
    {children}
  </body>
</html>
```

This gives the app a global font, color, and selection styling.

### app/page.tsx

This is the single-page application entry point. It composes the landing page in order:

1. Navbar
2. Hero
3. About
4. Services
5. Contact
6. Footer

This file is intentionally simple because the rest of the page content is sectioned into reusable component files.

## 6. Global styling and design system

### app/globals.css

This file defines the global visual language for the entire app.

Key utilities:

- `.text-balance` — improves text wrapping balance
- `.red-underline` — creates a red accent underline beneath section headings
- `.red-underline--center` — centers underline under headings
- `.gradient-text` — creates gradient text for emphasis
- `.glass` — translucent glass panel effect with blur
- `.noise-grid` — subtle grid background

Global rules:

- smooth scrolling is enabled via `html { scroll-behavior: smooth; }`
- body background and text colors are set
- reduced-motion support is applied to reduce animation intensity when the user requests accessibility-friendly motion
- custom scrollbar styling is applied for a polished desktop experience

### Design tokens

The palette is intentionally minimal and premium:

- background: white and soft gray
- accent: red tones with a warm corporate feel
- text: dark charcoal tones
- borders: light neutral lines

These values are centralized in `tailwind.config.ts` and reused across the site for consistency.

## 7. Component documentation

Each section below explains what the component does and how it contributes to the landing page.

### components/navbar.tsx

This component handles the fixed top navigation bar and mobile menu.

Features:

- fixed header that changes styling based on scroll position
- desktop navigation menu with active-link highlighting
- smooth scrolling to sections when menu items are clicked
- mobile menu with slide-in behavior
- scroll-based active section tracking using `IntersectionObserver`
- body scroll lock when the mobile menu is open

Important implementation details:

- The `NAV_LINKS` array defines the navigation destinations: Home, About, Services, Contact
- `scrolled` controls whether the header becomes glass-like and more visible
- `active` tracks the currently visible section
- `handleNavClick` scrolls to the selected section smoothly

This component is a good example of a UI element combining user interaction, accessibility, and state-driven behavior.

### components/hero.tsx

This is the primary visual centerpiece of the landing page.

Responsibilities:

- Displays the hero headline, subheading, and CTAs
- Uses GSAP to animate text and imagery into view
- Builds an energy-themed abstract illustration with layered rings, particles, and floating cards
- Includes mouse-based parallax and motion effects
- Uses counters to animate performance statistics in the hero area

Key concepts:

- `PARTICLES` is a static set of decorative points with motion properties
- `STATS_DATA` stores the data used in the animated stat counters
- `TRUST_BADGES` defines the trust/logo-style indicators shown beneath the CTA area
- `handleMouseMove` creates subtle parallax movement for the illustration and floating cards
- multiple GSAP timelines animate the entrance sequence, orbiting rings, and floating cards

This component is the most animation-heavy and visually rich part of the site.

### components/about.tsx

This section explains the company’s identity and operational philosophy.

It contains:

- a heading with the red underline design treatment
- narrative copy describing the company’s hybrid model
- animated statistics that count upward as the section enters view
- an SVG-based abstract illustration representing an integrated energy system

The section uses `gsap.from` with scroll triggers to create a clean reveal while the user scrolls to this block.

The metric data is defined in:

```ts
const STATS = [
  { value: 18, suffix: "+", label: "Years of Excellence" },
  { value: 34, suffix: "", label: "Global Partners" },
  { value: 42, suffix: "%", label: "Lower Emissions" },
];
```

### components/services.tsx

This section outlines the business offerings.

It presents four core services:

- Exploration & Production
- Renewable Integration
- Carbon Management
- Energy Consulting

Each service is represented as a card with:

- an icon
- a title
- a descriptive paragraph
- hover translation and border glow effects

The `SERVICES` array stores the content for each tile. GSAP is used to animate cards entering from below when the user reaches the section.

### components/contact.tsx

This component is a business contact and inquiry form.

Features:

- contact detail cards for office address, phone, and email
- social media icon links
- client-side validation for name, email, and message
- success and submitting states for the form
- GSAP entrance animation for the info panel and form fields

Form behavior:

- `validate(form)` checks required fields and email format
- `handleSubmit` prevents default submission
- if validation passes, it simulates a network submit with `setTimeout`
- the form resets after a successful submission

Important note:

This form currently simulates sending a message; in a production app it should be connected to a real API route or backend service.

### components/footer.tsx

A compact footer with:

- copyright notice using the current year
- a brand tagline line
- a subtle red divider at the top

This keeps the page polished and consistent with the premium corporate theme.

## 9. Shared libraries

### lib/gsap.ts

This file centralizes GSAP setup and registers `ScrollTrigger` only when running in the browser.

It exports:

```ts
export { gsap, ScrollTrigger };
```

This prevents repeated registration logic across components and keeps animation configuration consistent.

### lib/utils.ts

This file exports a small helper named `cn(...)` that merges Tailwind class names correctly.

Implementation:

```ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

This is especially useful when combining dynamic classes with conditional states in components.

## 10. Animation architecture

The project relies on GSAP for both entrance animations and subtle motion design.

Patterns used throughout:

- `gsap.from(...)` for fade/slide-in reveal effects
- `gsap.to(...)` for counters, parallax, and looping motion
- `ScrollTrigger` for scroll-responsive animations
- `gsap.context(...)` to scope animation behavior to a specific section
- `ctx.revert()` to clean up after component unmount

This keeps animations declarative and ensures they do not leak across sections.

## 11. Accessibility and UX notes

The project includes several accessibility considerations:

- semantic sections and headings
- keyboard-friendly navigation interactions
- focus styling inherited from the reusable button/input patterns
- reduced-motion media query support in `globals.css`
- proper `aria-label` values on icon-only social links
- mobile menu toggles with `aria-expanded` and accessible labels

## 12. Customization guide

### Updating company content

Most of the text is stored directly inside the component files. To change the wording:

- edit `components/hero.tsx` for the main headline and CTAs
- edit `components/about.tsx` for the overview section
- edit `components/services.tsx` for service descriptions
- edit `components/contact.tsx` for address and business contact details

### Updating visual branding

To adjust the company’s colors or theme:

- edit the `colors` block in `tailwind.config.ts`
- update utility styles in `app/globals.css`
- adjust section-specific gradient accents in component code

### Modifying animation behavior

Animations are defined in each component with `useEffect` and GSAP timeline logic. To change motion intensity:

- update durations and easing values in the GSAP calls
- adjust `scrollTrigger` start values
- reduce or remove loops for more subdued effects

### Connecting the contact form

The contact form is currently simulated. For production use, replace the `setTimeout` block in `handleSubmit` with a real API request, such as:

- a Next.js Route Handler in `app/api/contact/route.ts`
- an email service
- a CRM or database integration
